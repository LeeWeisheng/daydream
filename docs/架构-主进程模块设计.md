# Daydream 主进程架构（对齐 dsh-superagent-prototype）

> 本文档是主进程实现的开发者指南：把领域概念映射到类、接口与文件（对应 dsh-superagent 的 docs/007-architecture.md）。
> 配套文档：[实现方案.md](./实现方案.md)（总体设计）、[实现方案-Agent决策闭环设计.md](./实现方案-Agent决策闭环设计.md)（决策闭环机制）、[实现方案-数据模型与模块设计.md](./实现方案-数据模型与模块设计.md)（数据模型与模块）。

## 1. 概念映射（dsh → Daydream）

Daydream 的 Agent 架构按 dsh-superagent-prototype 的领域模型落地：

| dsh 概念 | Daydream 对应 | 说明 |
| --- | --- | --- |
| Source | 触发源（scheduler / user / workitem / pipeline / monitor） | 稳定 ID 派生，重放安全（`app/triggers.ts`） |
| Trigger | Agent 事件（`event_log` 行，含 disposition） | 幂等：同一 ID 只入一次 |
| Thread | 账户事件流（每账户一个，评估串行） | 进行中的评估与批次在内存；事件持久化于 event_log |
| Eval | 评估（两层：gate 确定性门槛 + assessment LLM 研判） | 明确请求直接接单，不经研判 |
| Decision | 决策（accept / stop / ignore / unavailable，落 `decision_record`） | 每次决策留输入快照与输出结论 |
| Mandate | 工作项授权依据（强度/依据/策略版本） | 记录于 `work_item.mandate_json` |
| Ticket | 工作项（`work_item`，open → ended） | 最小可管理单位 |
| Assignment | 工作项执行实例（一次尝试，落 `work_item_assignment`） | pending → running → ended |
| Policy | 运行策略：运行开关 + 运行模式（manual=observe / auto=auto）+ 自主级别 | 版本 = 模式+级别的哈希 |
| Outbox | 对话流消息出口（chat_message 唯一写者） | 先落 receipt（effect 行）再投递 |
| Effects | 持久化副作用队列（assessment / launch / reply） | 失败指数退避；重启可恢复 |
| Passes | 调度循环（副作用 → 评估到期 → 工作项调度） | 一次一个 pass |
| Executor | WorkItemExecutor + WorkerSlots（并发 2，同一业务对象串行） | 超时/重试/崩溃恢复 |
| Assessor | MasterAssessor（上下文组装 → LLM 研判 → 决策提交） | 失败按事件类型降级 |
| Sessions | LLM 会话门面（结构化输出 / Agent 会话，经桥接子进程） | 全部调用前过闸（llmGate） |
| Store | SQLite 仓储（领域聚合唯一写入路径）+ 读查询 | `app/store.ts` |
| KV | app_config 键值记录（`settings/service.ts` 集中声明键） | 模型配置/运行开关/模式/主题/数据偏好 |
| Runtime | 组合根（构造 Engine + Assessor + Executor + Outbox + Passes） | `runtime.ts` |

## 2. 分层与依赖规则

```
┌─ renderer / preload ── 展示与交互（白名单 IPC，不接触业务逻辑）
├─ ipc/ ──────────────── 按域拆分的薄 handler（账户/设置/行情/策略/交易/预警/Agent/对话）
├─ services/ ─────────── 业务服务（单写者）：accounts/strategy/trading/signals/alerts/reports/chat/settings
├─ pipeline/ ─────────── 七环节管线（确定性动作 + LLM 判断；经 PipelineHost 入队工作项）
├─ market/ quant/ ────── 行情数据（适配器/管线/服务）与确定性引擎（回测/风控/绩效，纯函数）
├─ agent/ ────────────── LLM 接入（bridge 子进程 / 工具集 / 提示词 / 消息归一化 / 闸门）
├─ app/ ──────────────── 应用装配：Store/Effects/Outbox/Passes/Assessor/Executor/Sessions/UiBus
├─ core/ ─────────────── 领域核心（纯领域，零 I/O）：Engine + Parts + Ports + 模型
└─ policy.ts ─────────── 授权与准入规则（gate / accept mode / 降级）
```

依赖规则（对齐 dsh 007-architecture）：

1. **core 不 import core 以外的任何模块**（Node 内置除外），不做 I/O；领域规则只在 core/policy。
2. **one writer per state**：Engine 是事件/评估/决策/工作项/执行实例的唯一写入者；
   chat_message 唯一写者是 Outbox；各业务表唯一写者是对应服务；app_config 唯一写者是 settings 服务。
3. **命令用祈使命名**（retryTicket / cancelTicket），**事实用过去式命名**（assignmentStarted / reportEnded）。
4. **窄接口**：调用方只拿到其角色的 Engine 子集（EngineForSources / EngineForMainSession / EngineForPeople / EngineForExecutor / EngineForPasses / EngineForPipeline / EngineForSettings）。
5. **固定拒绝**：一个人或 Agent 可触发的拒绝是 UserError(code)（`core/errors.ts`）；决策原因用 Reason 码（`core/reasons.ts`）。

## 3. Engine 内部部件

Engine 暴露一个入口，委托给五个内部部件（单向依赖）：

| 部件 | 职责 | 依赖 |
| --- | --- | --- |
| Intake | 事件接收：幂等落库、UI-only 过滤、gate 过滤、入队评估 | Tickets |
| Evals | 评估与决策：批次、直接接单、超时重排、决策落库、accept 建工作项 | Tickets |
| Tickets | 工作项生命周期：创建（Mandate）、重试/取消/结束、崩溃恢复 | — |
| Assignments | 执行事实：assignmentStarted / assignmentEnded | Tickets |
| Replies | 对话流消息（经 Outbox 单写者） | — |

## 5. 数据流（一次用户消息）

```
chat:send（ipc/chat）
  → chat.service.addChatMessage（Outbox：先落 receipt 再投递）
  → Engine.receive(user.message 触发)
      → Intake：gate（explicit/addressed）→ 落 event_log + 入队账户 Thread
  → Passes.evaluateDue（≤5s 一次）
      → Evals：明确请求直接接单 → 创建 user_request 工作项（Mandate 记录授权）+ Decision 落库
      → Executor.start → launch effect → WorkerSlots 获取槽位 → assignmentStarted
      → dispatch：runAgentTurn（bridge 子进程 agentic loop，工具 RPC 回主进程执行）
      → 会话消息经 messageSink → Outbox → 对话流（运行细节折叠）
      → reportEnded(succeeded) → Replies.ticketFinished → 对话流主要结果
```

## 6. 故障与恢复

| 场景 | 行为 |
| --- | --- |
| 评估失败（LLM 不可用） | 按事件类型降级：调度节律推迟重试（effect 退避）、用户消息直接接单、其余记录 ignore |
| 评估超时 | 重排两次，第三次记录 unavailable（决策留档） |
| 工作项失败 | 自动重试（attempts 保留），耗尽 → failed + workitem.failed 触发（评估可补救） |
| 停止运行/退出 | 闸门关 → 在途请求经桥接子进程组终止；执行中工作项 cancelled（不重试） |
| 应用崩溃重启 | running 工作项：可安全重跑类型重置 pending，其余 failed；effect 队列持久化可恢复 |
| 策略变更（运行模式切换） | 作废进行中的 Eval，事件重排（Policy version 语义） |
