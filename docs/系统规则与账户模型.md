# Daydream 系统规则与账户模型

> 本文档记录 Daydream 的账户模型、数据共享与隔离规则、模型配置规则与 Agent 能力边界，是系统行为的事实来源。配套文档：[实现方案.md](./实现方案.md)、[实现方案-Agent决策闭环设计.md](./实现方案-Agent决策闭环设计.md)、[实现方案-数据模型与模块设计.md](./实现方案-数据模型与模块设计.md)。

---

## 1. 账户规则

1. **必须创建账户**：首次打开软件且无账户时，必须先在账户创建向导中创建账户，才能进入主界面；系统不会自动创建默认账户。
2. **本地账户，无需登录**：账户是本地工作区（如"实盘 A""研究账户"），无任何云端登录；账户名称由用户自定义。
3. **账户可多开**：支持创建、切换、删除多个账户；切换账户即切换资金与持仓视角（顶栏账户切换器）。
4. **账户创建副作用**：新账户自动播种默认风控规则（仓位上限、ST 过滤、涨跌停防护、熔断等 8 条，见《实现方案-数据模型与模块设计》§7.2）。
5. **无账户时系统行为**：交易节律调度（盘前规划/盘中盯盘/盘后复盘等）不运行；Agent 闭环不产生事件；数据初始化与历史数据查询不受影响。

## 2. 数据共享与隔离规则

| 维度 | 归属 | 说明 |
| --- | --- | --- |
| 行情基础数据（股票列表、日线/分钟 K 线、指数日线、实时快照、数据状态） | **全局共享** | 所有账户共用同一份行情库，数据初始化/增量更新一次生效 |
| 策略库（strategy、strategy_version、回测记录、运行实例） | **全局共享** | 所有账户共用同一策略库；策略生成、回测、上线对全部账户可见 |
| 模型配置 | **全局通用** | 一套模型配置（API 地址/密钥/主模型/重型模型）服务所有账户 |
| Agent 研究产物（计划、工作项、复盘报告） | **账户级** | 按活跃账户记录与隔离 |
| 资金与持仓（position 持仓、trade_record 成交记录、account_snapshot 净值快照） | **账户级隔离** | 每个账户独立的资金、持股与净值 |
| 交易建议（signal 信号） | **账户级隔离** | 信号与资金强相关，按账户隔离；人工反馈闭环按账户记录 |
| 汇报与待决策（report）、预警（alert）、审计日志 | **账户级隔离** | 按活跃账户隔离 |

**核心原则：模型与通用数据全局通用；资金、持仓、信号等资金侧数据严格按账户隔离。**

## 3. 模型配置规则

1. **强制配置**：进入主界面后弹出模型配置模态框，未配置前不可关闭（无法跳过）；模型未配置时 Agent 决策闭环不运行（数据查询、回测等功能不受影响）。
2. **全局通用**：模型配置为全局唯一一份，所有账户共用；任一账户界面修改后全局生效。
3. **Anthropic 兼容 API**：支持原生 Claude 与 Anthropic 兼容端点（如 DeepSeek `https://api.deepseek.com/anthropic`）；支持双模型——主模型（评估/常规任务）与重型任务模型（策略生成/复盘/纠正，可选）。
4. **安全**：API Key 经 AES-256-GCM 加密存储（密钥材料经系统安全存储保护），永不回传明文，日志与审计不记录密钥。

## 4. Agent 运行规则

1. **运行开关**：顶栏提供「开始运行 / 停止运行」按钮。开始运行后，Agent 按规划持续自动运行（盘前规划 → 生成策略 → 回测 → 运行出信号 → 盘中盯盘 → 盘后复盘 → 纠正的完整闭环）；停止运行后，Agent 不再自动运行。开关状态持久化，重启后保持。
2. **开始运行前置条件**：必须已配置模型（全局）；未配置时开始运行会被拒绝并提示先配置模型。
3. **停止运行的边界**：停止后交易节律事件（规划/盯盘/运行决策/复盘）不再触发、自动工作项不再调度；数据增量更新照常（数据是全局基础设施）；用户主动对话（user_request）仍可用；正在执行的工作项自然完成。
4. **活跃账户视角**：Agent 决策闭环（规划→生成策略→回测→运行→盯盘→复盘→纠正）对**当前活跃账户**运行；信号产出、资金与持仓操作、预警、汇报均落在活跃账户上。切换账户即切换 Agent 的资金视角。
5. **AI 决策、人工执行**：系统只产出交易建议与预警，绝不执行真实交易；交易由人工完成，人工同时负责监督与兜底。
6. **策略全局、资金隔离**：Agent 生成的策略进入全局共享策略库（所有账户可用）；策略运行时的信号与资金操作严格按活跃账户隔离。
7. **少占用注意力**：仅在需要人决策或产出可用结果时汇报；其余活动只落审计。
8. **决策可追溯**：所有 LLM 调用、评估、决策、工作项均有审计记录，可完整回放"系统为什么这么做"。

## 5. Agent 能力清单（全部系统能力可被 Agent 调用）

Agent 经进程内 MCP 工具集（经 LLM 桥接子进程，工具在主进程执行）调用以下能力。**原则：所有能力均可被 Agent 调用**；其中涉及资金与安全的操作受权限与批准流程约束。

### 5.1 市场数据（8）

| 工具 | 说明 |
| --- | --- |
| `search_symbols` | 按代码/名称搜索 A 股标的 |
| `get_quote` | 实时行情快照 |
| `get_kline` | 日线 K 线（不复权 + 复权因子） |
| `get_index_overview` | 指数日线概览 |
| `get_market_breadth` | 市场简报（指数涨跌、涨跌家数） |
| `get_data_status` | 数据状态概览（各标的最后更新日） |
| `get_data_stats` | 数据统计（股票数、K 线行数、日期范围） |
| `trigger_data_update` | 触发当日数据增量更新（检测到数据缺失时主动调用） |
| `web_search` | 联网搜索最新信息（DeepSeek 原生搜索，返回总结与来源） |

### 5.8 人工专属操作（不开放给 Agent）

以下操作涉及资金与身份，**仅限人工**（保持"AI 决策、人工执行"边界）：

| 操作 | 原因 |
| --- | --- |
| 账户创建/切换/删除 | 资金视角切换属于用户意志 |
| 持仓维护（position upsert） | 真实持仓必须人工录入，Agent 不可篡改 |
| 成交记录录入（trade_record create） | 人工执行后的真实记录（信号反馈"已执行"时自动生成） |
| 信号反馈（已执行/已忽略） | 人工执行闭环，Agent 不可代反馈 |
| 模型配置修改 | 密钥与模型选择属于用户配置 |
| 待决策响应（批准/驳回/暂缓） | 需要人决策的事项必须由人决定 |
| 数据全量初始化（初建） | 长任务由用户在设置页触发（Agent 可触发增量更新与补数） |

## 6. 权限与安全约束

1. Agent 工具权限白名单：仅放行自有工具（`mcp__daydream__*`），其余能力（如任意代码执行、文件系统访问）一律拒绝。
2. 受限操作（策略激活/停用、淘汰纠正）默认走 `need_decision` 汇报，由人工批准；自主级别（保守/标准/激进）可配置，但任何级别下系统都不执行真实交易。
3. 信号产出前必经风控引擎校验（仓位/ST/涨跌停/熔断/偏离 8 项规则），校验拒绝的信号不落库不推送。
4. 所有 LLM 调用、工具调用、决策与工作项均有审计记录。
